# 如何放心地让 Agent 开展工作

> 一篇关于 Agent 可委托性的认知对齐材料。它不提供安慰，只提供判据。

---

## 一、先立对问题

过去两年，几乎每家公司都在做 Agent。做客服的、做代码审查的、做数据分析的、做招投标的——Demo 一个比一个漂亮。但走到一线问一句："有多少任务，你是真正交出去、不盯过程的？"答案寥寥。更常见的景象是：**Agent 做了一遍，人还要再做一遍。** Agent 写的报告，人逐句核；Agent 改的数据，人逐条对。复核一份 Agent 的产出，和自己动手做这件事，花的时间差不多。

这就是本文的冲突：Agent 的数量在涨，被真正委托出去的任务却没有。

流行的解释是"模型还不够强，等下一代"。这个解释听起来顺，但它把问题引向了等待。本文从一个更冷的问题出发：

> **什么条件下，把结果责任交给 Agent 而不盯过程，是理性的？**

先钉死一个词。标题里的"放心"，在本文中指的不是安全感，而是**有依据的信任**（warranted trust）。这个区别不是修辞。信任研究早就发现，人对自动化系统的信任感觉会系统性地失准——人对经常出错的系统过度放心，对相当可靠的系统疑神疑鬼；即便把系统的置信度直接展示给人看，人的依赖行为依然校准不良（Lee & See, [Trust in Automation, 2004](https://doi.org/10.1518/hfes.46.1.50_30392)；[CHI 2026 综述](https://dl.acm.org/doi/10.1145/3772318.3791467)）。所以"如何放心"如果理解成"如何让人产生放心的感觉"，那是一条通往灾难的路——坏系统最擅长制造安全感。本文要问的是：放心的**依据**从哪来。

## 二、拆解：委托为什么是四件事

"把一件事交出去"这个动作，经济学已经研究了五十年。委托代理理论（Principal-Agent Theory，Jensen & Meckling 1976）研究的就是：一个委托人，在什么条件下能把事交给代理人？拆开看，委托成立需要四个条件。

**条件一：目标一致。** 人类员工和你的利益并不天然一致，所以才有薪酬、晋升、声誉这一整套激励机制去对齐。Agent 没有私利——从这个角度看它完美忠诚，不存在"谋私"的问题。但代价是：激励机制这条通道对它完全失效，剩下的唯一通道是**说清楚**——它只会做你说的，不会做你想的。而"把想说的说清楚"这件事，远比看上去难，后面会讲到它难在哪。

**条件二：行为可观察。** 表面上看，Agent 比人类员工透明得多：每一步推理、每一次工具调用都有完整日志，人类员工的脑子你可看不见。但这里有一个悖论：**我们拥有空前的过程数据，却没有更多的理解。** 看一个员工做事，你能从共同的业务上下文推断他"懂了没有"；看 Agent 的完整轨迹，你依然不知道它哪一步理解偏了。数据不等于可观察性。于是可观察性的重心被挤到了最后一道闸上：结果验证。

**条件三：监督与问责。** 这两个词常被混用，但必须切开，因为它们的命运完全不同。监督——日志、抽检、评测——是可以工程化的；问责——做砸了承担后果——永远无法对 Agent 成立。Agent 不能赔钱、不能被解雇、不在乎声誉，它这次搞砸和下次搞砸，对它没有任何区别。监督可以补，问责补不了。

**条件四：风险可兜底。** 委托人敢放手，前提是最坏情况接得住。如果一次失败的损失无界，再高的成功率也换不来委托。

四个条件摆完，对照 Agent 的现状：条件一切了条窄通道，条件二有个悖论，条件三缺了一半，条件四靠人为设计。**缺口的总和，就是"人还要再做一遍"的全部内容**——现在的人不是流程里的"复核者"，而是所有缺失机制的肉身替代品：人肉验证器、人肉问责制、人肉信任校准器。

有人会反驳：这不就是磨合期吗？带新员工也要带半年，复核几个月，他就会了。

这个反驳必须正面接住，因为它有一半是对的：补位本身不是错，带新员工确实要补位。真正的区别在于**沉淀**。带人时，补位会沉淀——员工在成长，你复核的频率自然下降，半年后他可以独当一面。带 Agent 时，如果你在复核中磨出的那些判断——"这种数据要这么核""那种表述一看就有问题"——没有变成测试集、验收标准、示例库这些**资产**，那么补位就永远不会减少。半年后再看，你还在逐句核。**你不是在带徒弟，是在当永动机。** 问题从来不是补位，而是补位没有沉淀。

## 三、五条硬约束

补位该沉淀成什么？要回答这个，得先看清这个游戏里有哪些规则是撞不动的。

本文称它们为**硬约束**：技术进步消不掉、只能管理或定价的约束。辨认它们的最好方法，是跟着一个委托任务走一遍它的一生——从被交代，到被执行，到被拉长，到被检查，到被再次委托。

### 第一站：任务被交代——意图无法完整传递

委托的第一步是把任务说清楚。而这里压着一条哲学上早有定论的硬约束：**我们知道的多于我们能言说的**（Polanyi 悖论）。

一个业务任务的真实意图，大部分是默会知识：什么算"好"、什么情况算"异常"、哪些约束是死的哪些可以通融、客户上次为什么发火。这些东西在委托人的脑子里，以经验、品味、直觉的形式存在，能写进 prompt 和政策文档的只是冰山一角。人类员工可以用数年共事去浸泡这些默会知识，Agent 只能靠你写给它的东西。

这条约束解释了 τ-bench 实验里一个对企业管理者的极其重要的发现。τ-bench 是模拟真实业务场景（零售、航空客服）的 Agent 评测，要求 Agent 遵守书面政策完成多轮操作。对它的日志分析发现：**排除掉定义错误或含歧义的任务后，Agent 重复运行的成功率大致翻倍**（[arXiv:2605.08545](https://arxiv.org/pdf/2605.08545)）。换句话说，相当一部分被记在"Agent 不可靠"账上的失败，真正的责任人是**任务定义不清**——政策文档的歧义、验收标准的缺失。以为是模型问题，其实是管理问题。

它杀死的信念是："把文档丢给知识库，AI 就懂我们业务了。"

### 第二站：任务被执行——错误不可消除

任务交代完了，Agent 开始干活。第二条硬约束在这里：**开放任务上，错误不可消除，只能被管理和定价。**

大语言模型的输出本质上是概率分布上的采样。"错"不是 bug，而是方差——bug 可以修完，方差只能收窄不能删除。想把错误率真正压到零，只有一个办法：把任务收窄到封闭域，即答案确定、可完全枚举的那类问题。也就是说，**可靠性只能用任务范围来换**。

数据说的是同一件事。METR 对 2019–2025 年前沿模型的测量（[arXiv:2503.14499](https://arxiv.org/abs/2503.14499)）发现：最好的模型**偶尔**能完成需要专家数小时的任务，但**只能可靠地完成**几分钟量级的任务。能力涨了六七年，"偶尔能"和"可靠地能"之间的鸿沟没有闭合，只是位置上移。

注意，委托恰恰买在"可靠地能"上。你委托一件事，是因为相信它**每次**都会被做对，而不是有相当概率被做对。这条约束杀死的信念是："等模型足够好，就不需要流程和护栏了。"

### 第三站：任务被拉长——可靠性是乘法

单个步骤做得不错，那把二十步串起来呢？第三条硬约束是算术：**可靠性是乘法，不是加法。**

单步可靠性 95%，连续二十步，端到端成功率的上界是 0.95 的 20 次方——约 36%。这不是工程经验，是条件概率。实情还要再糟一点：Agent 是有状态的，一步的错误会改变后续所有步骤的轨迹——Anthropic 在构建多 Agent 系统的复盘里反复提到，"错误会复利累积，一步失败会让 Agent 走向完全不同的方向"（[Anthropic Engineering](https://www.anthropic.com/engineering/built-multi-agent-research-system)）。当然也有反向的修正：检查点、重试这类恢复机制能挽回一部分。两个修正项不改变主结论：链条越长，对单步可靠性的要求越苛刻，而单步可靠性被第二条硬约束压在 1 以下。

把第二、第三条放在一起，会推出一个可以在原理层面**定性预言**实验结果的结论：成功率必然随任务长度快速下跌。这正是 METR 实测到的那条曲线——看到它时你不该意外，它不是某种模型缺陷，是算术。

这条约束杀死的信念是："这个 Agent 每步都做得挺好，串成完整流程应该没问题。"

### 第四站：结果被检查——验证与生成不对称

任务做完，轮到委托人检查。第四条硬约束在这里，它可能是五条里最反直觉的：**验证成本与生成成本不对称，且这个不对称随模型变强而加剧。**

生成是采样，验证是对照真值——这两件事的成本没有任何必然关系。解一道数独要很久，验证一个解只要一眼；反过来，核查一篇长文的每个事实，比写这篇长文还累——网上造谣和辟谣的成本差距有个专门的说法，Brandolini 定律：驳斥胡说八道所需的能量比制造它高一个数量级。Jason Wei 把这个现象总结为"验证不对称"，并指出一个任务的"可验证性"决定了 AI 解决它的速度上限（[verifier's law](https://www.jasonwei.net/blog/asymmetry-of-verification-and-verifiers-law)）。

关键推论在"加剧"两个字上：模型变强，压低的只是生成端的成本，验证端分毫不动。生成越便宜，涌向验证端的工作量越大，验证就越成为瓶颈。**所以"模型变强"不仅不解决委托问题，反而让瓶颈更集中地暴露在验证上。** 这也解释了真实世界的一个现象：Anthropic 基于约百万条真实对话的 Economic Index（[来源](https://www.anthropic.com/news/the-anthropic-economic-index)）显示，AI 自动化最集中的领域是软件开发——不是因为模型最懂代码，而是因为**代码自带验证器**：编译器、测试、类型系统，都是现成的结果校验。市场已经在用脚投票：先被委托的，永远是验证便宜的任务。

这条约束杀死的信念是："Agent 产出越多，组织效率越高。"——超出验证吞吐的产出，不是资产，是负债。

### 第五站：关系在延续——信任攒得很慢

假设前四站都过了：任务定义清晰，错误率可接受，链条够短，验证也便宜。是不是就可以全面委托了？还有最后一条硬约束，它长在委托人这一侧：**委托关系的深化速度，受限于验证记录的积累速度；而验证记录的积累速度，受限于人的注意力与真值的可得性。**

信任不是能力的函数，是验证记录的函数。能力可以七个月翻一倍（METR 的时间跨度曲线），但人消化结果、积累证据的速度不变；更麻烦的是，人这一侧还会退化——Bainbridge 在 1983 年的经典论文《自动化的讽刺》里就指出（[来源](https://doi.org/10.1016/0005-1098(83)90046-8)）：自动化程度越高，人的实际操作经验越少，一旦需要接管，反而更没有能力接管。

这条约束解释了为什么"benchmark 分数到了，组织就会用起来"是错的：能力曲线和委托曲线之间，有一个由验证吞吐决定的、不可压缩的时间差。采纳必然滞后，而且应该滞后——没有验证记录支撑的提前信任，正是第一节说的"没有依据的放心"。

## 四、五个机会

硬约束读下来容易丧气。现在换个方向——查理·芒格管这个叫逆向思维：不问"怎样让 Agent 可信"，反过来问"**是什么让我不敢委托**"。把每一条"不敢"列出来，逐条翻转，每一条都是可投资的工程方向。

五条硬约束，恰好对应五条"不敢"，也恰好对应五个机会。

### 机会一：意图资产化

> "我不敢，因为它不懂我们的业务，做出来方向是偏的。"

既然意图不可完整传递，那就把"传递意图"本身当成工程对象，把传出去的那部分建成**资产**：可执行的验收标准、黄金示例库、被消过歧的政策文档。注意"资产"和"文档"的区别：文档写完放进 wiki 就死了，资产是持续维护的工程制品——每次复核发现 Agent 理解偏了，纠正的同时把这个判断沉淀成一条示例或一条验收标准，下一次复核就少一件事。τ-bench 那个"排除歧义后成功率翻倍"的发现说的就是这项资产的收益率：**先修任务定义，比先修 Agent 本身更值钱。**

这也是第二节"永动机"问题的解药：人肉补位要沉淀，沉淀的去处就是意图资产。

### 机会二：错误预算制

> "我不敢，因为不知道它哪次会错。"

既然错误不可消除，那就放弃"零错误"的幻想，把错误从恐惧对象变成管理对象。这套纪律有一个成熟的现成版本：Google 的 SRE 从不追求 100% 可靠的系统，而是给系统设**错误预算**——预算之内，放手跑；预算耗尽，冻结变更、全力还债。移植到 Agent 上：建立失败模式分类学（它会以哪几种方式出错），每类错误有预算、有检测手段、有处置路径；预算内自主运行，预算外自动升级给人。

要坦白一句：这是五个机会里证据最弱的一个。它是从运维领域**类比移植**来的纪律，还没有人系统验证过"Agent 错误预算"在实践中的效果。但它的前提——错误不可消除——是五条硬约束里最硬的一条，所以方向不赌错。

### 机会三：短链装门

> "我不敢，因为它单步都挺好，一长就崩。"

既然 p 的 n 次方不可违抗，就不要跟它对抗，而是管理 n。两个动作：**切短**，把长任务分解成短链条；**装门**，在链条之间插入确定性的、程序化的检查点——通过闸门才进入下一段，通不过就停在原地。配合检查点恢复（checkpoint/resume），出错从断点继续，而不是从头再来。Agent 的自主只发生在门与门之间的短区间里——**自主性不是被取消了，而是被装进了笼子里，笼子的大小由你定。**

Anthropic 的工程实践正是这个思路：把任务切成固定子任务的 prompt chaining，在步骤之间加入程序化检查（[Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents)）。

### 机会四：验证前置

> "我不敢，因为确认它做对了，比我自己做还贵。"

验证成本是任务的属性，但可以被前置成**工程资产**——这是五个机会里杠杆率最高的一个，因为它是其他几个的前提：错误预算需要检测手段，授权阶梯需要信任证据，意图资产需要验收标准，全部来自验证器。

验证资产有两条腿。**第一条是结果验证**：测试集、答案键、终态校验（不看过程，只比对最终状态对不对——τ-bench 正是用"比对最终数据库状态"来判分的）。**第二条是过程审计**：Agent 留下的完整执行轨迹——每一步推理、每一次工具调用——可回放、可审计、可评测。第二条腿常被忽视，但它是 Agent **独有**的资产：人类员工永远不可能给你这样的透明度。可观察性悖论说的是"数据不等于理解"，而工程化的回答是把数据变成审计能力。

一份验证资产同时服务三层：开发期的评测、上线前的验收、运行时的护栏。一次投入，三次产出。

### 机会五：授权阶梯

> "我不敢，因为一次事故，一年的信任就归零。"

既然信任只能由验证记录逐笔累积，那就把这个累积过程**制度化**——像带实习生一样带 Agent：只读观察 → 出建议 → 审批后执行 → 限定范围自主 → 扩大范围。每一级的晋升标准用指标说话，不用感觉说话——核心指标是 pass^k：同一任务独立运行 k 次、每次都成功的概率。单次成功是演示，次次成功才是委托。τ-bench 的实测给过清醒剂：最强的 Agent，跑 8 次全都成功的概率低于 25%（[arXiv:2406.12045](https://arxiv.org/abs/2406.12045)）。

阶梯的两个配套设计：一是**闸门**——高风险动作（支付、删除、对外发送）无论爬到哪一级都强制人工批准，OpenAI 的 Agent 实践指南把"失败超阈值"和"高风险动作"列为两类必须的人工介入触发器（[A Practical Guide to Building Agents](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)）；二是**演练**——保留人定期手动操作的习惯，否则按 Bainbridge 的警告，"human-in-the-loop"会退化成名义上在环、实际上接不住。

有实验证据支持这套设计：按置信度阈值做条件委托——高于阈值自动执行，低于阈值转人工——团队表现可以超过人或 AI 任何一方单独作战（[Confidence-Based Trust Calibration, 2025](https://thesai.org/Downloads/Volume16No12/Paper_122-Confidence_Based_Trust_Calibration_in_Human_AI_Teams.pdf)）。

五个机会摆完，回看第二节的四条件：意图资产化补上目标一致的窄通道，验证前置补上可观察性，错误预算制和短链装门补上监督那半个，授权阶梯补上风险兜底——**四个条件补上了三个半。剩下的半个，是最后一节的事。**

## 五、做法：先做什么，怎么判断一个任务能不能委托

五个机会不是平均投资的。排序依据两套逻辑，分层使用：

**第一位不靠诊断，靠依赖。** 验证前置永远先动工——不是因为你的瓶颈恰好在那，而是因为它在结构上就是使能器：错误预算要靠它检测，授权阶梯要靠它供证据，意图资产里的验收标准本身就是验证器的一种。这不是经验判断，是结构判断。

**第二位起靠诊断。** 在意图资产、错误预算、短链装门之间，打你当前最紧的那个约束。简易诊断：任务总是跑偏——先建意图资产；流程一长就崩——先短链装门；出了错没人管、反复犯同类错——先立错误预算。

**授权阶梯贯穿始终。** 它不是一步投资，而是一种姿势：从第一天起，让 Agent 在最低一级（只读观察）真实运行，边跑边攒验证记录。等它"够格"再上线的思路是错的——资格只能在真实的、低权限的运行中挣出来。

落到单个任务上，能不能委托，四个问题，按顺序问：

| 问 | 答"否"怎么办 |
|---|---|
| ① 任务能被完整给定吗？——验收标准、示例写得出来吗？ | 先建意图资产，别急着上 Agent |
| ② 验证能前置吗？ | 定位增强模式（Agent 出草稿，人负责），不装委托 |
| ③ 一致性够吗、链条超半径吗？——pass^k 实测多少？ | 短链装门，缩小自主区间 |
| ④ 最坏损失接得住吗？ | 加闸门，压低授权阶梯级数 |

四问全过，才是委托候选。这个表值得你忘掉本文所有论证之后仍然带走。

至于经济账，一个任务值不值得委托，可以用一条公式记：委托收益 = 人亲自做的成本 −（Agent 执行成本 + 验证成本 + 失败率 × 失败损失），大于零才委托。它是第①②问的成本估算工具——仅此而已，本文不指望它解释更多。

## 六、边界：三个"永远"

五个机会把委托代理的四个条件补上了三个半。现在说补不上的部分——这门课不是 Agent 布道文，它画的是委托的版图：哪里可以，以及**哪里永远不行**。五条硬约束推出三个"无论模型多强都不变"的边界。

**经济边界：验证约等于重做的任务，永远不委托。** 事实核查密集的长文、高度依赖品味的创意——这类任务里"确认它对了"和"自己做一遍"一样贵，委托的经济性永远不成立。对它们，诚实的定位是增强：Agent 出草稿、出线索、出初稿，人对结果负责。把增强包装成自动化，是当下 Agent 项目最常见的自欺。

**风险边界：不可逆、高损的动作，永远保留人工闸门。** 支付、删除、对外发送、修改生产数据——这些动作一旦发生无法撤回。授权阶梯可以一级级爬，但闸门不随级数取消。这不是阶段性的谨慎，是永久的架构。

**责任边界：问责永远无法对 Agent 成立，残余责任永远由人承担。** Agent 不能赔钱、不能坐牢、不在乎声誉——问责这个条件在原理上就无法对它满足。无论机制建得多完善，每一个被委托的任务，都必须有一个有名有姓的人类 owner 对结果负责。一篇立场论文把这一点推到了最强表述：完全自主、不预留人类接管的 Agent 系统，本身就不该被开发（[Fully Autonomous AI Agents Should Not be Developed, arXiv:2502.02649](https://arxiv.org/abs/2502.02649)）。

到这里，可以解开本文表面上的一个矛盾了。第二节说，人是缺失机制的"肉身替代品"，补位应当被资产化消灭；这一节又说，人永远要留在流程里。人到底该在还是不该在？

答案是：补位补的是**缺的机制**——验证、监督，这些能建成资产，建成之后人应当退出；裁决担的是**不可转移的责任**——问责，这个建不成资产，人必须留下。该资产化的补位全部资产化之后，人剩下的唯一角色就是裁决者：

> **人不是被挤出流程，而是被推到流程中唯一不可替代的位置。**

---

## 七、回到开头的问题

第一节的问题是：什么条件下，把结果责任交给 Agent 而不盯过程，是理性的？

现在可以回答了。当——意图被资产化地给定，而不是指望它"懂"；错误被定价和预算，而不是被假装不存在；自主链条被控制在可靠性半径之内；验证被前置成资产，而不是靠人肉复核兜底；授权沿阶梯逐级挣得，而不是第一天全量开放；并且，有一个有名有姓的人守在裁决的位置上——这时候，放心是理性的。

所以，"如何放心地让 Agent 开展工作"的最终答案是：**放心不是一种感觉，也不能靠等待下一代模型批发得来。它是一套机制运转的副产品。** 机制到位的团队，今天就可以放心；机制缺位的团队，再强的模型来了，也还是"Agent 做一遍，人再做一遍"。

模型的能力曲线会继续涨，这不由任何人决定。但委托时代的到来速度，取决于有多少人开始动手建机制。
